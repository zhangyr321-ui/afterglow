# 余温 · Afterglow

一本只存在自己设备上的日记。一天一页，可以写字，也可以只放照片；写过的页隔夜封存，正文里可以选中一句话留下旁注。

这个项目从 Ember 的“日记柜”概念出发，但没有使用 Supabase、账号或任何服务器。文字和照片都保存在浏览器本地。

## 功能

- 一天一页：同一天只能有一页，隔天自动变成只读
- 文字日记：正文、时间感、每日之字
- 照片日记：从相册选择或直接拍照，一页最多 6 张
- 旁注：选中正文中的一句话，写下当时的想法
- 册页：按月份排列所有日记
- 字历：把每天的那个字排成月历
- 备份：导出包含文字、旁注和照片的 JSON 文件
- 导入：支持本项目的备份，也兼容 Ember 的导出数据

## 启动

需要 Node.js 18 或更新的版本，不需要安装依赖：

```sh
npm start
```

然后打开 <http://127.0.0.1:5188>。

ES 模块需要通过 HTTP 访问，直接双击 `index.html` 不能用。

第一次打开会看到两页示例日记，用来演示时间感、字历和旁注。它们只存在于当前浏览器里，可以在“设置 → 清空这本册子”里删掉。

## 数据存在哪里

- 日记、旁注和照片：浏览器的 IndexedDB（数据库名 `afterglow-diary`）
- 册子名字、署名：`localStorage`

数据不会上传到任何地方。代价是：

1. 清除浏览器站点数据会一起清掉日记；
2. 换浏览器、换设备不会自动同步；
3. 无痕模式关闭后内容会消失。

所以请定期在“设置 → 备份与迁移”里导出 JSON。

照片会在浏览器里压缩到最长边 1600 像素，再存进 IndexedDB。一页最多 6 张，单张原图上限 25 MB。支持浏览器能解码的 JPG、PNG、WebP、AVIF 等格式；iPhone 的 HEIC 是否可用取决于浏览器。

## 使用

1. 点右上角的笔，或首页的“写今天”
2. 选一个时间感，留一个“今日之字”
3. 写正文，或者点“选照片 / 拍一张”
4. 点“收进柜子”

当天写的内容在当天还可以编辑。过了午夜，页面会显示“已封存”，只读。

想写旁注时，用鼠标或手指选中正文里的一句话，底部会出现“写旁注”。旁注会附着在那句话上；如果之后修改了正文，能找到原句的旁注会自动重新定位，找不到的会标成“原文已改”但仍然保留。

## 备份与恢复

- **导出全部**：生成 `余温备份-YYYY-MM-DD.json`，照片以 data URL 形式包含在内。
- **导入备份**：按日期合并。相同日期会以导入文件中的那一页为准，旁注按 id 去重。

导入 Ember 的 `ember_entries` / `ember_annotations` JSON 也可以，字段会自动转换，旁注偏移会尽量按原文重新定位。

## 部署到 GitHub Pages

这是一个纯静态站点，把整个 `afterglow/` 目录上传到仓库，然后在 GitHub 仓库的 **Settings → Pages** 里选择分支根目录即可。

页面没有构建步骤，也没有环境变量。部署后数据仍然只存在每个访客自己的浏览器里，不会汇总到服务器。

### 上传步骤

1. 在 GitHub 新建一个空仓库，不要额外生成 README。
2. 解压 `afterglow-github-20261020.zip`，把里面的 `index.html`、`assets/` 等所有文件上传到仓库根目录。
3. 打开仓库的 **Settings → Pages**。
4. 如果使用分支发布：Source 选 **Deploy from a branch**，Branch 选 `main`，目录选 `/ (root)`，保存。
5. 如果使用仓库自带的 Actions：Source 选 **GitHub Actions**，推送到 `main` 后会自动生成 `dist/` 并部署。

两种方式任选一种即可，不要同时依赖。发布地址通常是：

```text
https://你的用户名.github.io/仓库名/
```

GitHub Pages 首次部署可能需要一到两分钟。仓库里的 `.github/workflows/pages.yml` 已经配好自动部署；不使用 Actions 时可以直接忽略它。

## 分享给别人

手机和电脑在同一个 Wi-Fi 下时，可以直接打开电脑的局域网地址。`npm start` 会打印类似：

```text
局域网：http://192.168.1.23:5188
```

路由器开启了“访客隔离”或 Windows 防火墙拦截 Node 时，手机可能打不开，这时需要换网络或允许 Node 通过防火墙。

如果只是临时给不在同一网络的人看，可以用 Cloudflare Quick Tunnel：

```sh
cloudflared tunnel --url http://127.0.0.1:5188
```

它会生成一个临时的 `https://*.trycloudflare.com` 地址。电脑关机、睡眠或进程结束后链接就失效，重启后地址通常会变化。

要一个长期稳定的链接，不要用临时隧道。国内访问优先选择腾讯云 CloudBase 静态托管、阿里云 OSS 静态网站等国内服务；Cloudflare Pages、GitHub Pages 免费但国内访问速度不稳定。正式托管通常需要账号、实名或备案，具体取决于服务商和域名。

**分享链接分享的是网站程序，不是日记内容。** 每台手机打开后都有自己的本地空册子；要让别人看到你写的某一页，需要另外做“导出备份给对方导入”，或者做一个发布只读快照的功能。

## 开发

```sh
npm test
```

测试覆盖日期与月历、文字/照片校验、旁注区间与重叠、正文修改后的旁注重定位、Ember 数据导入和按日期合并。

主要文件：

- `index.html`：页面骨架
- `assets/app.js`：界面、路由、写作、旁注和备份
- `assets/model.js`：纯数据逻辑与校验
- `assets/db.js`：IndexedDB 封装
- `assets/photos.js`：照片压缩与 data URL 转换

调试时可以给地址加 `?storage=memory`，页面会使用内存示例数据，不写入浏览器数据库：

```text
http://127.0.0.1:5188/?storage=memory
```

## 说明

“余温”是受 Ember 启发的独立实现，视觉、交互和代码都重新写过。原项目使用 Supabase 作为云端数据库；“余温”刻意去掉了这一层，换成完全本地的存储。
